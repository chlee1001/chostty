## Platform

## Stack

Static HTML/CSS in `website/`, deployed to GitHub Pages by a GitHub Actions workflow. No framework or build step. Pages on the free plan serves only from a public repository; the repository is still private, so the deploy stays inert until the owner makes it public.

## Users

Primary: macOS developers who already use Ghostty and live in several terminals at once. They want related shells grouped by project without giving up their Ghostty config, themes, or terminfo. Secondary: macOS developers on other terminals (iTerm2, Warp, Terminal.app) who juggle many tabs and want them grouped. Both arrive from the GitHub repository, a link, or search, decide in under a minute, and leave by downloading the DMG.

## Product Purpose

Chostty is a macOS terminal: a fork of Ghostty that replaces native window tabs with an in-window Workspace → Tab → Pane hierarchy driven from a left sidebar. Success for the landing page is a visitor who understands the hierarchy, trusts that their Ghostty setup carries over unchanged, and downloads the release.

## Positioning

One physical window owns the whole Workspace → Tab → Pane graph, shown in one sidebar, on top of an unmodified Ghostty renderer, config format, and terminfo. Upstream Ghostty gives every tab its own `NSWindow`; Chostty removed AppKit native tabs entirely and enforces their absence with an audit gate.

## Operating Context

- Install: download the DMG from GitHub Releases, drag to Applications. Universal binary, macOS 13 or later. Developer ID signed and notarized.
- Updates through Sparkle from this repository's signed appcast. `auto-update = off|check|download` controls it.
- Reads `~/.config/ghostty/config`, same keybinding and theme syntax, `TERM=xterm-ghostty`. Ghostty and Chostty can be installed side by side.
- Reserved shortcuts: `⌘N` new workspace, `⌘T` new tab, `⌘⇧N` new physical window, `⌘1`–`⌘8` workspace by index, `⌘9` last workspace, `⌘⇧[`/`⌘⇧]` previous/next tab, `Ctrl+Tab`/`Ctrl+⇧+Tab` previous/next workspace, `⌘⇧T` reopen closed tab, `⌘B` toggle sidebar.
- Structure persistence: workspaces, tabs, pane layout and working directories return after a restart as fresh shells; terminal contents are never written to disk. Only the selected tab starts a shell at launch; the rest materialize on first selection.
- Files panel on the right opens read-only document tabs (Markdown, source, JSON/YAML/TOML/XML/plist, images, static HTML, Quick Look) inside the selected tab without unmounting the terminal.

## Capabilities and Constraints

- Current release: 1.0.0, the first stable Chostty release. Chostty versions are independent of Ghostty's.
- macOS only. Linux/GTK code is inherited and not built.
- Bundle identifier `kr.co.devch.chostty`; 0.2.15 and older used `com.chostty.app` and migrate on first launch; macOS privacy permissions must be granted again.
- Download URL pattern: `https://github.com/chlee1001/chostty/releases/latest` (DMG asset `Chostty-<version>.dmg`).
- Free and open source under MIT, upstream notice retained.

## Brand Commitments

- Name: Chostty. Not affiliated with or endorsed by the Ghostty project; this must be stated on any public surface. The Ghostty name and logo belong to their owners and are not used as Chostty branding.
- App icon: generated by `macos/scripts/generate-icons.py` — a window with a workspace sidebar, a split pane and a `>_` prompt. Assets in `images/icons/` (16–1024 px PNG) and `images/Chostty.icon/`. The icon must be preserved.
- Voice: plain, factual, engineer-to-engineer. README and FORK.md set the tone; no hype.

- No real screenshots of the app are committed. No users, testimonials, download counts, benchmarks, or press exist; none may be invented. Illustrations of the UI must be labelled as illustrations.

## Product Principles

1. Ghostty underneath stays Ghostty: config, themes, terminfo and rendering are never Chostty's to change.
2. Structure is the product: grouping shells by workspace is the one idea, everything else supports it.
3. Say what is true and nothing more; limits are documented, not hidden.
4. Keep the user's state safe: migrations copy, never move; persistence never writes terminal contents.

## Accessibility & Inclusion

No product-specific standard established. Default to WCAG 2.2 AA for the landing page. Content in English with a Korean version available for the docs.
